# Backend (FastAPI)

Python API for the car rental platform. See the root [README.md](../README.md)
for the project overview and stage tracker.

## Setup

Start PostgreSQL first (from the repository root, see [Database](#database)):

```bash
cp .env.example .env        # repository root: set POSTGRES_PASSWORD
docker compose up -d db
```

Then set up the backend:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt   # runtime + test/lint tools (requirements.txt = runtime only)
cp .env.example .env                  # local settings; never commit .env
# edit .env: put the POSTGRES_PASSWORD from the root .env into DATABASE_URL and TEST_DATABASE_URL
alembic upgrade head                  # create the schema
```

## Run

```bash
uvicorn app.main:app --reload --port 8000
```

- Health check: http://localhost:8000/api/v1/health
- Interactive docs (non-production only): http://localhost:8000/docs (Swagger UI), http://localhost:8000/redoc
- OpenAPI schema: http://localhost:8000/api/v1/openapi.json

When `APP_ENV=production`, `/docs`, `/redoc`, and the OpenAPI schema are disabled.
`/api/v1/health` returns `"database": "ok"` (200), or `"database": "unavailable"`
with status 503 when PostgreSQL cannot be reached.

## Database

PostgreSQL 16 runs in Docker for local development (`docker-compose.yml` at the
repository root). It listens on `127.0.0.1:5433`, so it does not clash with a
system PostgreSQL on 5432. On first start the container creates two databases:
`car_rental` (development) and `car_rental_test` (automated tests).

```bash
docker compose up -d db              # start (from repository root)
docker compose ps                    # health status
docker compose stop db               # stop, keeping data
docker compose down -v               # DELETE the database volume (all local data)
```

Migrations (run in `backend/` with the venv active):

```bash
alembic upgrade head                           # apply all migrations
alembic downgrade -1                           # revert the last migration
alembic current                                # show the applied revision
alembic revision --autogenerate -m "message"   # create a migration from model changes; review it before committing
alembic check                                  # fail if the models and migrations differ
alembic upgrade head --sql                     # print the SQL without running it
```

Rules:
- The schema changes only through Alembic migrations, never by hand.
- Review every autogenerated migration. Alembic does not detect everything (e.g. triggers, extensions, seed data).
- Models live in `app/models/`. Import new modules in `app/models/__init__.py` so Alembic sees them.

### Transactions

Routes get a session from the `get_db` dependency (`app/db/session.py`). Service
code calls `session.commit()` explicitly when a unit of work succeeds. If the
request raises, the session is rolled back. Nothing is committed implicitly.

### Integrity rules enforced by PostgreSQL

| Rule | Mechanism |
|------|-----------|
| No overlapping reserving bookings per vehicle | `EXCLUDE USING gist (vehicle_id WITH =, tstzrange(start_at, end_at, '[)') WITH &&) WHERE status IN (...)` (`btree_gist`) |
| Booking price snapshot is internally consistent | `rental_amount = daily_rate * rental_days`, `total_amount = rental_amount + delivery_fee` |
| Exact money in ZAR | `NUMERIC(12,2)`, `currency = 'ZAR'`, non-negative/positive checks |
| One successful payment per booking | Partial unique index on `payments(booking_id) WHERE status = 'SUCCEEDED'` |
| Provider transactions recorded once | Unique `(provider, provider_reference)` |
| One delivery per booking | Unique `deliveries.booking_id` |
| Case-insensitive unique emails | Unique index on `lower(email)` |
| Valid enum values | `VARCHAR` + `CHECK` constraint per enum |
| Audit log is append-only | Trigger rejects `UPDATE`/`DELETE` on `audit_logs`; users with audit history cannot be hard-deleted (`RESTRICT`) |
| Price history is kept | `vehicle_prices` rows referenced by bookings cannot be deleted (`RESTRICT`) |

`PENDING_PAYMENT` bookings keep blocking their dates until their status changes. A
CHECK constraint cannot compare against `now()`, so the booking service (Stage 10)
marks expired holds as `EXPIRED` before it checks availability.

## Test and lint

```bash
pytest -ra             # automated tests (-ra lists skipped tests and the reason)
ruff check .           # lint
ruff format --check .  # formatting
```

Database tests need `TEST_DATABASE_URL` (from the environment or `backend/.env`).
The database name must end in `_test`, because **the test run drops and recreates
its `public` schema** through Alembic. Without that variable, database tests are
skipped and reported by `pytest -ra`.

## Configuration

Settings come from environment variables, or from `backend/.env` when running from `backend/`.
See [.env.example](.env.example).

| Variable | Default | Description |
|----------|---------|-------------|
| `APP_ENV` | `development` | `development`, `test`, `staging`, or `production` |
| `APP_NAME` | `Car Rental API` | Shown in API docs and the health response |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, or `CRITICAL` |
| `CORS_ORIGINS` | *(none)* | Comma-separated allowed browser origins |
| `DATABASE_URL` | **required** | `postgresql+psycopg://USER:PASSWORD@HOST:PORT/DB` |
| `TEST_DATABASE_URL` | *(none)* | Test database (name must end in `_test`), used only by pytest |
| `DATABASE_ECHO` | `false` | Log every SQL statement (debugging only) |

## Structure

```
app/
├── main.py            # create_app() factory: middleware, error handlers, routers
├── core/
│   ├── config.py      # Settings (pydantic-settings) and dependencies
│   ├── errors.py      # AppError base class and the error-envelope exception handlers
│   └── logging.py
├── api/
│   ├── router.py      # Mounts route modules under /api/v1
│   └── routes/        # One module per resource (health.py)
├── db/
│   ├── base.py        # Declarative Base, naming convention, Money type, mixins
│   └── session.py     # Engine, session factory, get_db dependency
├── models/            # SQLAlchemy models (one module per aggregate) and enums
└── schemas/           # Pydantic request and response models
migrations/            # Alembic environment and versions/
tests/                 # Pytest suite; tests/db/ runs against real PostgreSQL
```

Business logic goes in `app/services/` (added with the first feature that needs
it, Stage 05). Route handlers stay thin.

## Error format

Every error response uses the same envelope:

```json
{"error": {"code": "validation_error", "message": "Request validation failed.",
           "details": [{"location": ["body", "seats"], "message": "...", "type": "int_parsing"}]}}
```

Validation errors never echo the submitted values. Unexpected errors return a
generic 500 message and are logged on the server with the full traceback.
Services raise subclasses of `AppError` (with `status_code` and `code`) for
expected business errors.
